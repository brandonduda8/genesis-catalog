# genesis-catalog

The remote catalog and config for **[Genesis Player](https://github.com/brandonduda8/genesis-player)**. The app fetches these JSON files at runtime, so tracks, playlists, labels and theme can change without shipping a new APK. Nothing here is audio: every entry points at a stream (Audius, or a SoundCloud permalink resolved at play time), so nothing is downloaded or stored.

## Files

| File | What it holds |
|---|---|
| `catalog.json` | `version`, `generated_at`, `track_count`, and `tracks[]`. Each track has `artist`, `title`, `audius_stream_url` or `soundcloud_url`, `genre`, `mood`, `source`, `why`, `verified_206`, and the `playlists` it belongs to. |
| `config.json` | UI labels, visible sections (Now Playing, Library, For You, EQ) and theme colours. |
| `apollo_suggestions.json` | `pending[]` track suggestions from the Apollo curator, awaiting a keep/skip decision in the app. |

## How it's used

- The player reads `catalog.json` and `config.json` on launch and on **Refresh music**, applying a new catalog only when its `version` is newer. The player's CI gate covers remote catalog pickup, a config theme change and the offline fallback.
- `track_count` must equal `tracks.length`, and **Full Blend** is the playlist that contains every track.
- The app fetches files via `raw.githubusercontent.com/brandonduda8/genesis-catalog/master/…`. The default branch is now `main`; GitHub currently redirects the old `master` path, but pointing the app at `main` would remove that dependency.

## Updating

Catalog updates are generated by the Apollo curation pipeline and committed here; bump `version` on every change so installed apps pick it up.

## Validation

`tools/catalog_validate.py` is a stdlib-only, deterministic checker (no network, no stream probes; it never prints stream URLs). Run it locally:

```
python3 tools/catalog_validate.py selftest
python3 tools/catalog_validate.py remote catalog.json --allowlist tools/allowlist.txt
```

It checks that `track_count` matches `tracks[]`, that every track has an artist, title and a stream URL (or a soundcloud.com permalink that the app resolves at play time), that every track is in **Full Blend**, and that there are no duplicate normalized artist+title pairs unless listed in `tools/allowlist.txt`. With `--base-file <older catalog.json>` it also fails when `tracks[]` changed but `version` was not raised above the base. Live stream health is out of scope here on purpose, because network probes are flaky.

The `catalog-validate` workflow runs the self-test as a hard gate and the catalog check in report-only mode until the duplicate cleanup lands. This file has no track ids, so duplicate-id checks cannot run on it.
